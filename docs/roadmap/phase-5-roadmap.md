# Phase 5 Roadmap

## Objective

Phase 5 designs and implements a paper-only execution architecture for the AQuantLens US/options branch.

The goal is to let reviewed Strategy Lab candidates enter a controlled paper workflow while preserving the existing safety boundary: no live broker execution, no broker credentials, no AI-directed live trading authority, and no order placement outside a paper adapter.

## Entry State

Phase 4 completed the research-only Strategy Lab experiment workbench:

- Saved strategy experiments.
- A/B experiment comparison.
- Research-only strategy catalog boundary.
- Experiment curation with tags, notes, and archived state.
- Review gate with draft, reviewed, candidate, and rejected states.
- Candidate Review Board for active candidate experiments.

Reference completion audit: `docs/roadmap/phase-4-completion-audit.md`.

## Design Principles

- Paper-first, live-never-by-default.
- Every trading-class action begins as an intent, not an order.
- Agent-originated actions require explicit scope, idempotency, audit, and risk checks.
- Human review remains the default promotion path from candidate research to paper simulation.
- Runtime state must be database-backed; no JSON-file or in-memory production persistence.
- Broker interfaces remain contract-only in Phase 5 until a separate decision approves a concrete adapter.

## Core Contracts

### Paper Account

A paper account represents simulated capital, currency, and account-level controls.

Minimum fields:

- Paper account id.
- Name.
- Base currency.
- Starting cash.
- Current cash.
- Status: active, paused, archived.
- Created time.

Not included:

- Broker account identifiers.
- Broker credentials.
- Real account balances.
- Live buying power.

### Order Intent

An order intent is a proposed paper action generated by a user workflow or approved agent workflow.

Minimum fields:

- Intent id.
- Source: human, agent, or system.
- Source reference: candidate experiment id, analysis run id, or manual note.
- Symbol.
- Asset class: equity, ETF, index-option, equity-option.
- Side: buy or sell.
- Quantity.
- Order type: market, limit.
- Limit price when required.
- Time in force.
- Status: draft, risk_rejected, awaiting_review, approved_for_paper, paper_submitted, paper_filled, paper_cancelled.
- Idempotency key.
- Created time.

Not included:

- Live order id.
- Broker routing target.
- Account number.
- Execution venue selection.
- Automated live approval.

### Risk Guard

RiskGuard validates an intent before it can reach the paper adapter.

Initial checks:

- Paper account is active.
- Symbol is inside the configured instrument allowlist.
- Asset class is inside the Phase 5 paper scope.
- Quantity is positive.
- Limit price is positive when present.
- Estimated notional is under per-intent limit.
- Estimated daily notional remains under paper account limit.
- Options intents require contract identity and expiry metadata.
- Source reference exists when the intent is generated from a Strategy Lab candidate.

RiskGuard returns:

- Decision: pass or reject.
- Machine-readable reason codes.
- Human-readable explanation.
- Normalized estimated notional.

### Paper Execution Adapter

The paper adapter simulates fills and positions. It does not contact brokers.

Allowed:

- Accept approved paper intents.
- Create paper fills.
- Update paper positions and cash.
- Record audit events.

Forbidden:

- Network calls to broker APIs.
- Reading `.env` broker credentials.
- Accepting broker credentials through API payloads.
- Returning live account state.
- Reusing live broker SDK order methods.

### Audit Trail

Every trading-class step must append an audit record.

Required events:

- Intent created.
- RiskGuard passed or rejected.
- Human review approved or rejected.
- Paper adapter accepted intent.
- Paper fill created.
- Paper position updated.
- Intent cancelled.

Audit records must include actor type, source, resource id, action, outcome, reason code, and created time. They must not include secrets.

## Explicit Non-Goals

- Live broker order placement.
- Broker credential storage or mutation.
- Broker account balance sync.
- Live order status sync.
- AI-direct live trading authority.
- Trading-scope MCP tools that can reach a broker.
- Automatic promotion from candidate to paper without review.
- Automatic promotion from paper to live.
- Multi-account or multi-user trading operations.
- Production PnL accounting beyond paper simulation.

## Required Safety Checks Before Any Phase 5 Implementation

Before code implementation begins, write a task-level implementation plan that includes:

- Failing tests before behavior changes.
- Exact files to create or modify.
- Explicit no-broker grep checks.
- Ubuntu verification commands.
- Documentation update steps.
- A final audit section that confirms paper-only scope.

## Completion Criteria

Phase 5 is complete only when:

- Paper account, order intent, RiskGuard, audit, paper fill, and paper position contracts exist.
- All paper mutations are database-backed and audited.
- Candidate-to-paper flow requires explicit review.
- Paper adapter performs no broker network calls.
- Tests prove rejected intents cannot reach paper submission.
- Project docs and Yasin Brain record that live execution remains out of scope.
